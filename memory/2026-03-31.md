## 需求管理页面打开报错修复
- 结论：Requirement 页面首屏报 `Minified React error #130`，根因是前端把 `@arco-design/web-react` 的 `Typography.Link` 当成可渲染组件使用；当前依赖版本的 `Typography` 并不提供 `Link` 静态子组件，运行时实际为 `undefined`。
- 改动文件：
  - `frontend/src/pages/Requirement/index.tsx`
  - `frontend/src/pages/Requirement/style/index.less`
- 改动说明：
  - 将标题列的 `Typography.Link` 替换为原生按钮样式链接，避免渲染 `undefined` 组件。
  - 新增 `.requirement-title-link` 样式，保持表格内点击态与现有视觉一致。
- 验证：
  - `cd frontend && npm run build` 通过（webpack compiled with 2 warnings，均为既有体积/less 警告）
  - `cd backend && GRADLE_OPTS='-Dorg.gradle.native=false' gradle classes` 通过
- 风险：
  - 低。仅影响 Requirement 列表标题点击节点的渲染方式，不涉及接口、状态流转和数据结构。

## 需求管理页面表格高度自适应对齐待办页
- 结论：已将 Requirement 页面表格高度自适应逻辑对齐到 Todo 页面同款实现，避免继续维护页面专属的高度计算链路。
- 改动文件：
  - `frontend/src/pages/Requirement/index.tsx`
  - `frontend/src/pages/Requirement/style/index.less`
- 改动说明：

  - 将 `.requirement-page` 容器样式收敛为仅保留 `height: 100%`，避免额外 flex/overflow 设置影响 DataManager 高度继承。
- 验证：

  - `cd frontend && npm run build` 未完成收口：当前环境仅输出 `baseline-browser-mapping` 提示后未返回退出码，暂未拿到成功或失败结论
- 风险：
  - 低。仅调整 Requirement 列表页前端表格滚动高度计算，不涉及接口、状态流转和数据结构。
